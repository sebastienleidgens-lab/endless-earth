# Préparation des décorations stables

Les reliefs, occupations des sols et règles de provenance restent dans le contrat géographique normalisé de Mission 08.5. Un second produit, `static-decorations-v1`, contient les résultats déterministes du générateur artistique. Il ne transforme pas les arbres procéduraux ou les hauteurs de bâtiments interprétées en observations mesurées.

`npm run geo:decorations` lit les données validées, exécute les générateurs canoniques hors navigateur et écrit `public/data/angles-decorations`. Les originaux lourds restent hors Git. Le manifeste conserve les empreintes des trois entrées, celles du code de génération, la provenance, les licences, le millésime, l'emprise, la projection locale métrique et le statut d'interprétation. Un changement d'entrée ou de générateur impose une nouvelle préparation. Les tests vérifient ces empreintes et la référence 08.5.

Chaque bloc est un conteneur binaire compressé gzip : longueur de l'en-tête JSON, descripteurs, alignement sur quatre octets, attributs et indices typés. Les positions, normales, couleurs, UV, attributs de vent et indices sont copiés sans quantification supplémentaire. Les sphères englobantes précalculées évitent leur recalcul sur le thread principal. Le navigateur vérifie SHA-256, taille, version, types et bornes avant de créer les vues typées des buffers.

Le paquet statique porte les bâtiments de base. Les 250 cellules naturelles et 67 cellules de détails architecturaux sont indépendantes. Les arbres instanciés utilisent les 2 500 recettes canoniques du manifeste et les matériaux existants. L'état environnemental partagé et les shaders d'animation restent séparés des données stables ; aucune simulation individuelle permanente n'est ajoutée par arbre.

La file priorise la proximité, précharge selon le profil et la vitesse, limite à deux téléchargements, deux résultats prêts ou en vol et une installation par image. Les cibles CPU d'installation sont de 0,5 ms en Éco, 0,8 ms en Équilibré/Personnalisé et 1,2 ms en Qualité, ramenées à 0,25 ms après une image de plus de 50 ms. Ce sont des cibles, pas des garanties : une installation indivisible et le parcours de la file peuvent dépasser la cible. Les maxima observés sont exposés dans les diagnostics. Aucun nouveau panneau de réglages n'est créé.

Les caches existants gardent au plus quatre cellules naturelles invisibles et douze cellules architecturales invisibles, plus les cellules actuellement nécessaires. Les places de préchargement sont réservées dans ces limites afin d'éviter l'alternance téléchargement/éviction. Un changement de destination annule les tâches périmées ; un résultat tardif est détruit et jamais installé. Les buffers de cellules évincées sont libérés. Les arbres et bâtiments de base demeurent présents pendant le chargement des détails.

Si le manifeste ou le paquet statique manque, est corrompu ou ne correspond plus aux sources, le générateur déterministe historique sert de repli, avec son coût CPU initial. Un détail manquant conserve la géographie et les collisions de base, produit un avertissement et ne déclenche pas de boucle de tentatives. La préparation doit être livrée atomiquement avec ses sources.

Le pilote possède une zone active et une file associée. Une extension mondiale utilisera un manifeste et une file par zone active, avec un budget global partagé avant d'autoriser plusieurs zones simultanées. Le format ne dépend d'aucun fournisseur national : un import étranger normalisé peut alimenter le même générateur, avec sa propre provenance, ses styles et ses coordonnées locales. Il faudra héberger et versionner les blocs de façon progressive pour un monde entier ; les 32,6 Mo du pilote ne sont pas une stratégie de téléchargement global.
